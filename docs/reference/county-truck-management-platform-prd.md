## Executive Summary

县域大货车基础信息管理平台旨在为县级公安交警大队提供一套完整的大货车档案管理与监管工具。当前，多数县域对大货车的管理仍依赖 Excel 表格或纸质台账，存在数据分散、更新滞后、统计困难、安全设备监管缺位等突出问题。随着上级公安机关对重点车辆源头监管要求的不断提高，以及辖区内大货车事故预防的实际需求，建设一套信息化管理平台已是迫在眉睫。

本系统覆盖车辆档案管理、辖区主体（企业/个人车主）管理、数据看板、Excel 数据导入导出、组织架构与 RBAC 权限管理、审计日志六大核心模块。采用"全模块简化版"MVP 策略——每个模块都做，但第一阶段只交付最核心的功能，后续迭代增强。系统部署于公安内网环境，服务规模为 1 个大队 + 3~5 个中队、并发用户不超过 20 人、管理车辆数不超过 5000 辆。

**本项目的重大技术决策**：基于已引入的 **RuoYi-Vue3-FastAPI** 开源后台管理框架进行二次开发。该框架已提供用户/角色/菜单/部门/字典/日志/文件管理等通用后台能力，我们只需在此基础上新增"大货车管理"业务模块。经分析，**约 60% 的系统功能可直接复用框架现有能力**，大幅缩短开发周期。

项目成功以四个维度衡量：**数据完整度**（建档率 90%+）、**查询与监管效率**（查询从分钟级降至秒级、安全设备覆盖率实时可知）、**审计合规**（操作全日志满足网安要求）、**领导决策支撑**（看板一键掌握全局，无需等中队手工汇总）。

### 代码生成器加速

RuoYi-Vue3-FastAPI 内置代码生成器（`module_generator/`），支持以下模板：

```
templates/
├── python/    → controller.py, service.py, dao.py, do.py (实体), vo.py (视图对象)
├── js/        → api.js (前端接口封装)
├── vue/       → index.vue (列表页), index-tree.vue (树形列表页)
└── sql/       → 建表 DDL
```

**使用方式**：在数据库设计好表结构后，通过代码生成器一键生成后端 CRUD + 前端列表页的基础代码，然后在此基础上手写业务逻辑。预计可节省 **50-60%** 的 CRUD 样板代码编写时间。

## Problem Statement

**当前状况**：县域交警大队对大货车的管理普遍存在以下痛点——

- **台账分散、效率低下**：车辆信息分散在多个 Excel 文件或纸质档案中，查找一辆车的信息可能需要翻找 10 分钟以上；
- **统计靠人工、时效性差**：领导要了解全县车辆分布、安全设备安装率等数据时，需要各中队人工统计后逐级上报，耗时数天且容易出错；
- **安全设备监管缺位**：上级要求推动辅助刹车、360 环视、右转语音提示等安全设备安装，但缺乏系统化手段跟踪每辆车的安装情况，难以精准督办；
- **归属关系不清**：车辆挂靠、个人购买等情况复杂，一辆车属于哪个企业/个人、归哪个中队管辖，缺乏清晰的数字化关联；
- **审计追溯困难**：谁在什么时候改了哪条数据，没有日志记录，无法满足网安审计要求。

**解决方案**：构建一套县域级大货车基础信息管理平台，以车辆档案为数据核心，建立"车辆 → 归属主体（企业/个人） → 辖区中队"的关联体系，通过数据看板实现宏观可视化，通过 RBAC 权限控制实现分级管理，通过操作日志实现全链路审计追溯。

**业务影响**：
- 车辆建档率从现状（假设 < 60%）提升至 90%+；
- 单车信息检索从分钟级降至秒级；
- 安全设备安装覆盖率从"说不清"变成"实时可知、精准督办"；
- 满足上级公安机关信息化考核和网安审计要求。

## Success Metrics

**主要 KPI：**

| 指标 | 目标值 | 衡量方式 |
|------|--------|----------|
| 车辆建档率 | ≥ 90% | 系统建档车辆数 / 辖区内应纳入管理车辆总数 |
| 信息检索效率 | ≤ 10 秒 | 从输入车牌号到展示完整档案的响应时间 |
| 安全设备覆盖率统计 | 实时可查 | 看板中"已安装/应安装"数据在录入后即时更新 |
| 审计合规度 | 100% 操作可追溯 | 每一条数据变更均有操作日志，登录行为全量记录 |
| 领导满意度 | 上报数据时间从数天 → 0 | 看板数据实时反映，不再需要中队手工汇总上报 |

**验证方式**：系统上线后 1 个月内，由大队管理员对比系统数据与原有台账，计算建档率；随机抽查 20 辆车进行检索速度测试；组织一次网安审计模拟检查。

## User Personas

### 主要角色：大队管理员
- **角色定位**：交警大队秩序科/车管所负责人
- **目标**：掌握全县大货车底数，查看各中队辖区统计数据，导出报表向上级汇报
- **痛点**：数据散落在各中队，每次统计都要催收、合并，耗时耗力且不准确
- **技术水平**：中级（能熟练使用办公软件，但对复杂系统接受度一般）
- **功能权限**：查看全部数据、管理组织架构、配置角色权限、字典维护、导出报表

### 次要角色：中队录入员
- **角色定位**：各交警中队内勤人员
- **目标**：录入和维护本辖区车辆档案，关联企业和个人车主，记录安全设备信息
- **痛点**：车辆信息变更频繁（转户、报废、设备加装），纸质记录容易遗漏和出错
- **技术水平**：初级至中级（日常使用电脑办公）
- **功能权限**：仅可查看和编辑本辖区数据，录入和导入车辆信息

### 其他角色：领导（只读）
- **角色定位**：大队领导（大队长、教导员等）
- **目标**：打开即看全局看板，快速了解重点监管车辆情况
- **痛点**：每次需要数据都要下面的人临时统计，等待时间长
- **技术水平**：初级（偏好简洁直观的界面）
- **功能权限**：仅查看数据看板和不涉配置的查询功能，不可编辑

### 其他角色：系统管理员
- **角色定位**：IT 运维或指定管理员
- **目标**：配置系统基础参数、管理用户账号、查看审计日志
- **痛点**：用户权限混乱时需要手动排查
- **技术水平**：高级
- **功能权限**：用户管理、角色分配、字典配置、日志查看

## User Stories & Acceptance Criteria

### Story 1: 车辆档案录入与查询

**作为** 中队录入员
**我想要** 录入一辆大货车的基础信息并关联归属主体
**以便** 建立完整的车辆电子档案，后续可快速检索

**Acceptance Criteria:**
- [ ] 录入页面包含：车牌号、车牌颜色（下拉选择）、车辆类型（下拉选择）、车架号(VIN)、核定载重、来源标识（本地/外地）
- [ ] 车牌号 + 车牌颜色联合校验唯一性，重复时提示"该车辆已存在，请检查"
- [ ] 关联归属主体时，通过下拉搜索选择运输企业或个人车主（允许跨中队选择：挂靠车辆的主体与车辆分管中队可以不同）；车辆分管中队由车辆自身确定，不随主体带出
- [ ] 支持上传车辆照片（单张，限制 5MB，支持 jpg/png 格式）
- [ ] 安全设备支持"增行"方式同时录入多个设备（设备类型下拉 + 产品名称/品牌 + 安装时间）
- [ ] VIN 码自动转为大写，长度校验为 17 位
- [ ] 提交成功后跳转到车辆详情页

### Story 2: 首页数据看板

**作为** 大队管理员/领导
**我想要** 在首页一眼看到全县大货车的核心统计数据
**以便** 快速掌握全局态势，无需等待人工汇总

**Acceptance Criteria:**
- [ ] 页面顶部展示全县车辆总数，含三个卡片：总车辆数、本地车辆数、外地车辆数
- [ ] 辖区多维统计以表格形式展示：每个中队辖区一行，列包含：车辆总数、运输企业数、个人车主数、安全设备安装覆盖率（已安装/应安装 × 100%）、重点监管预警数
- [ ] 安全设备安装覆盖率支持以柱状图直观展示各中队对比
- [ ] 点击中队名称可下钻查看该中队辖区车辆列表
- [ ] 点击"重点监管预警数"可查看预警车辆详情列表
- [ ] 数据 5 分钟内自动刷新一次（或支持手动刷新按钮）

### Story 3: Excel 批量导入

**作为** 中队录入员
**我想要** 通过 Excel 模板批量导入车辆信息
**以便** 快速将历史台账数据迁移到系统中

**Acceptance Criteria:**
- [ ] 系统提供标准 Excel 导入模板下载
- [ ] 上传 Excel 后，系统逐行校验数据格式（车牌号非空、VIN 码位数等）
- [ ] 校验通过的行自动入库，校验失败的行标注错误原因，支持下载错误行 Excel
- [ ] 校验规则与手动录入一致（唯一性、必填项、格式校验）
- [ ] 支持车辆档案数据导出为 Excel（按辖区、按状态等条件筛选后导出）
- [ ] 单次导入上限 500 行，超过时提示分批导入

### Story 4: 安全设备与预警管理

**作为** 大队管理员
**我想要** 对未按要求安装安全设备的车辆进行预警标记
**以便** 精准定位督办对象，推动安全设备全覆盖

**Acceptance Criteria:**
- [ ] 系统根据预设的"应安装设备清单"与每辆车的实际安装记录，自动标记缺装车辆
- [ ] 预警等级支持配置。**实际实现口径**：应安装设备为「刹车辅助系统 + 360 全景影像」共 2 项，
  缺失 2 项 = 一级预警 `level_one`，缺失 1 项 = 二级预警 `level_two`，无缺失 = 无预警 `none`；
  阈值存于 `truck_warning_rule.level_one_threshold` / `level_two_threshold`（当前为 2 / 1）。
  > 注：本节早期草案曾写「缺装 ≥3 项为一级」，与实现不符，已按代码更正；
  > 若业务要求改为 3/2 口径，需同时调整该表阈值与 `truck-platform-init.*.sql`。
- [ ] 预警车辆在看板中以醒目颜色（红/黄）标识
- [ ] 支持导出预警车辆列表（Excel）
- [ ] 预警规则中的"应安装设备清单"由大队管理员在字典/配置中维护

### Story 5: 组织架构与权限管理

**作为** 系统管理员
**我想要** 配置大队-中队组织层级并为用户分配角色
**以便** 实现数据按辖区隔离和权限分级控制

**Acceptance Criteria:**
- [ ] 组织管理支持大队 → 中队的二级层级，中队隶属于唯一大队
- [ ] 用户管理支持创建、禁用、重置密码操作
- [ ] 角色权限基于 RBAC 模型：角色可自定义，权限细粒度到菜单/按钮级别
- [ ] 预设角色：大队管理员（全部数据+全部功能）、中队录入员（仅本辖区数据+录入导出）、领导（只读看板+查询）、系统管理员（配置+用户+日志）
- [ ] 用户必须关联到具体的组织节点（大队或中队），中队用户的数据访问范围自动限定为本辖区
- [ ] 权限变更实时生效，无需用户重新登录

### Story 6: 操作与登录日志

**作为** 系统管理员
**我想要** 查看所有用户的操作日志和登录日志
**以便** 满足网安审计要求，追溯异常操作

**Acceptance Criteria:**
- [ ] 操作日志记录：操作人、操作时间、IP 地址、操作类型（增/删/改/查）、操作模块、操作前后数据变化（JSON 格式）
- [ ] 登录日志记录：登录人、登录时间、IP 地址、登录结果（成功/失败及失败原因）
- [ ] 日志支持按时间范围、操作人、操作类型筛选
- [ ] 日志不可删除、不可修改（只能查看和导出）
- [ ] 日志保留时间 ≥ 6 个月（系统自动归档过期日志）

## Functional Requirements

### 核心功能模块

#### 模块 1: 首页数据看板

- **描述**：系统首页，以卡片 + 表格 + 柱状图组合展示全县车辆核心统计指标
- **用户流程**：
  1. 用户登录后默认进入看板页面
  2. 顶部三张卡片显示：全县车辆总数、本地车辆数、外地车辆数
  3. 下方表格列出各中队辖区统计（车辆数、企业数、个人数、安全覆盖率、预警数）
  4. 安全覆盖率配有柱状图视图切换
  5. 点击预警数可下钻查看预警车辆列表
- **边缘情况**：辖区或车辆数为 0 时显示"0"而非空白；数据加载失败时显示友好错误提示并提供重试按钮
- **错误处理**：后端数据查询超时（> 10 秒）时前端显示加载中状态，超时后提示"数据加载较慢，请稍后刷新"

#### 模块 2: 辖区主体管理

- **描述**：管理运输企业和个人车主两类归属主体
- **企业信息字段**：企业名称、统一社会信用代码、所属辖区中队（关联组织架构）、联系人、联系电话、地址
- **个人车主信息字段**：姓名、身份证号、所属辖区中队、联系电话、地址
- **用户流程**：
  1. 列表页按辖区筛选，支持名称/姓名模糊搜索
  2. 新增主体时选择所属中队
  3. 查看主体详情时，关联展示该主体名下所有车辆列表
- **边缘情况**：删除主体前校验其下是否有未转移的车辆，如有则阻止删除并提示
- **错误处理**：统一社会信用代码/身份证号格式校验不通过时给出明确提示

#### 模块 3: 车辆档案管理

- **描述**：平台的数据核心，记录每辆大货车的完整档案
- **基础信息字段**：车牌号、车牌颜色、车辆类型、车架号(VIN)、核定载重、车辆照片、来源标识（本地/外地）
- **归属信息字段**：归属类型（企业/个人）、关联主体（下拉搜索）、辖区中队（自动带出）
- **安全设备字段**：设备类型、产品名称/品牌、安装时间（支持一车多设备）
- **状态标签字段**：车辆状态（正常/报废/转出等，下拉选择）、标签（重点监管等，自动+手动）
- **用户流程**：同 User Story 1
- **边缘情况**：
  - 车辆转出/报废后，历史数据保留但标记为不可再编辑
  - 车辆归属主体变更时需记录变更历史
  - 车牌号+车牌颜色组合唯一性校验
- **错误处理**：VIN 码重复时警告但允许保存（存在真实重复场景）

#### 模块 4: 数据采集与导入导出

- **描述**：提供手动录入和 Excel 批量导入两种数据采集方式，以及灵活的导出功能
- **导入流程**：
  1. 用户下载模板 → 按模板填写数据 → 上传 Excel
  2. 系统展示预览列表，标注校验结果
  3. 用户确认导入 → 系统逐行入库
  4. 展示导入结果（成功 X 条、失败 Y 条），支持下载失败行
- **导出流程**：
  1. 用户在车辆列表页设置筛选条件（辖区、状态、归属类型等）
  2. 点击"导出 Excel"，系统导出当前筛选结果的所有字段
- **边缘情况**：空文件上传提示"文件无数据"；大文件（> 500 行）提示分批导入
- **错误处理**：模板格式不符时给出具体错误说明

#### 模块 5: 系统基础管理

- **描述**：组织架构管理、角色与权限管理、字典管理
- **组织架构**：大队 → 中队的二级树形结构，支持增删改
- **角色权限**：基于 RBAC，角色关联菜单/按钮权限，用户关联角色 + 组织节点
- **字典管理**：配置以下下拉框选项——
  - 车辆类型（重型货车、牵引车、自卸货车等）
  - 车牌颜色（黄牌、蓝牌、绿牌等）
  - 设备类型（辅助刹车、360 环视、右转语音提示等）
  - 车辆状态（正常、报废、转出、停运等）
  - 来源标识（本地、外地）
- **边缘情况**：删除字典项前校验是否已被车辆数据引用，如已引用则阻止删除并提示
- **错误处理**：删除组织节点前校验其下是否有子节点或关联用户/车辆，如有则阻止并提示

#### 模块 6: 系统监控与日志

- **描述**：操作日志 + 登录日志，满足网安审计要求
- **详细需求**：同 User Story 6
- **边缘情况**：日志存储空间达到阈值时系统告警提示管理员清理或扩容

### Out of Scope（本期不做）

- ❌ 移动端 App 或小程序
- ❌ 与公安交管六合一平台/运管系统的数据对接（架构预留接口，实现放入二期）
- ❌ 车辆 GPS/北斗轨迹监控
- ❌ 车辆年检到期提醒、保险到期提醒
- ❌ 大屏可视化（LED 大屏投放版本）
- ❌ 数据 API 对外开放
- ❌ 工作流审批（如车辆状态变更审批流）

## Technical Constraints

### 性能要求

- 页面首次加载时间 ≤ 3 秒（内网环境）
- 车辆列表查询响应时间 ≤ 2 秒（5000 条数据量级）
- 看板统计数据查询 ≤ 5 秒
- 单次 Excel 导入 500 行处理时间 ≤ 30 秒
- 并发用户数：最大 20，日常 5-10

### 安全要求

- **部署环境**：纯内网部署（公安内网或政务内网），不与互联网直接连通
- **认证方式**：用户名 + 密码登录，密码要求 ≥ 8 位含数字+字母，支持连续失败锁定（5 次失败锁定 30 分钟）
- **权限控制**：RBAC 模型，粒度到菜单/按钮级，数据按辖区隔离
- **数据保护**：数据库密码加密存储（bcrypt），关键操作二次确认
- **审计合规**：操作日志（含变更前后数据快照）+ 登录日志，日志不可删除，保留 ≥ 6 个月（满足等保二级要求）
- **会话管理**：空闲超时 30 分钟自动退出

### 集成要求

- **本期**：独立系统，不集成外部数据源
- **架构预留**：车辆档案数据结构预留"外部系统编号"字段；设计 RESTful API 接口规范，便于二期对接公安交管平台
- **数据交换格式**：统一使用 JSON（API）/ Excel（人工交换）

### 技术栈（基于 RuoYi-Vue3-FastAPI）

| 层级 | 技术 | 版本/说明 |
|------|------|----------|
| **后端框架** | Python FastAPI | Python 3.10+，异步非阻塞 |
| **ORM** | SQLAlchemy asyncio | 异步数据库操作 |
| **数据库** | MySQL 8 | 默认（也支持 PostgreSQL 14） |
| **缓存** | Redis | 会话管理 + 字典缓存 + 数据权限缓存 |
| **认证** | OAuth2 + JWT | 无状态 token 认证 |
| **任务调度** | APScheduler | 定时任务（可用于日志归档等） |
| **数据库迁移** | Alembic | 版本化 schema 管理 |
| **后端工具链** | Ruff（lint）、pytest（单测） | 代码质量 |
| **Web 前端** | Vue 3 + Vite | Composition API |

## Appendix

### Glossary

| 术语 | 定义 |
|------|------|
| **大队** | 县级公安交警大队，系统的最高组织层级 |
| **中队** | 交警大队下属的辖区中队，每个中队管辖一定区域内的车辆 |
| **辖区** | 中队的地理管辖范围，车辆通过归属主体自动关联到辖区 |
| **运输企业** | 以企业形式注册的运输公司/物流公司，名下有多辆大货车 |
| **个人车主** | 以个人名义拥有大货车的车主 |
| **归属主体** | 运输企业或个人车主的统称 |
| **安全设备** | 安装在货车上的安全辅助设备，如辅助刹车、360 环视、右转语音提示等 |
| **重点监管预警** | 系统根据预设规则自动标记需要重点关注的车辆（如安全设备缺装、逾期未年检等） |
| **RBAC** | Role-Based Access Control，基于角色的访问控制模型 |
| **VIN** | Vehicle Identification Number，车辆识别代号（车架号），17 位 |
| **等保** | 网络安全等级保护制度，公安系统通常要求等保二级及以上 |
